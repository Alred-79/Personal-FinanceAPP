## Context

The app is shifting from a professional tracker toward a **gamified finance app** — the numbers
stay legible, but the theme leans into play. v3 is a **toolbox of independent modules** sharing
one engine. Originally the flagship was Debt Boss Battles; market research (below) shows that
concept is **already shipped**, so v3's value must come from *integration depth* and *ethics*,
plus a hedge of genuinely novel mechanics.

## The two real edges (how we differentiate non-unique concepts)

1. **Integration depth.** Incumbents (esp. Hunter Vault) are offline/manual and award XP for
   *typing in expenses* — which quietly rewards logging/spending. We have Plaid sync + v1 forecast
   (`project_cashflows`) + Safe-to-Spend + the rules engine. Mechanics that need **live data** are
   the moat: boss **"defeat-by-date"** from the real forecast; **auto-attack via round-up rules**
   (v1 enabler: generic rule target → `pay_liability`); a boss that **heals when a real recurring
   bill is missed**.
2. **Ethics as differentiator.** Reward **saving / paydown / consistency — never logging or
   spending.** Better than incumbents and a marketing line.

## Proven vs. experimental landscape

- **Proven & sticky:** prize-linked savings (Yotta, Long Game; Truist +$37M/6mo); peer comparison
  (Status Money study); pet+streak (Finch); personality/AI roast-or-hype (Cleo).
- **Emerging:** RPG/quest finance (Hunter Vault, new); city-builder (Fortune City, niche).
- **White space (no finance products found):** **roguelike "monthly runs," idle/incremental
  "money machine," procedural antagonists from live analytics.** Real novelty lives here.

## Module menu

### Core (market-validated; differentiate via integration + ethics)
- **R1 — Debt Boss Battles** (flagship): `Liability` model; HP = balance; payments = damage;
  above-min = crit; APR = boss heal; **defeat-by-date from `project_cashflows`**; round-up
  auto-attack via the v1 generic-target rule. Habit-monsters (no schema) from over-budget
  categories + subscriptions.
- **R2 — RPG stat engine** (shared substrate): HP=runway, Mana=savings rate, Armor=on-time
  bills+budget adherence, Attack=net-worth growth/debt paid, Level/XP = *good-behavior* events
  only. Character sheet + ambient avatar/level pip + level-up toasts.
- **R3 — AI Dungeon-Master narrator** (Cleo-style, reuse `assistant_service` + Groq): roast/hype
  narration over the data; customizable persona with memory.

### Experimental (white space; novel, riskier)
- **X1 — Roguelike months:** each month is a run with a drafted modifier + random events (surprise
  expense = trap/mini-boss), meta-progression across months. Months already ARE the cycle.
- **X2 — Idle/incremental money machine** *(deferred):* savings rate spins up passive generators;
  net-worth milestones = prestige.
- **X3 — Procedural antagonists** *(generic version deferred; regret-monster in scope):* worst
  category → a named monster seeded from analytics.

## AI-native gamification (leverage the existing Groq agent)

`assistant_service.py` is already an **agentic LLM**: a LangChain tool-calling agent over Groq
with read tools (transactions/accounts/goals/spend), **Tavily web search + hardened web-fetch**,
and a **propose → confirm → execute** safety model (LLM never writes; it mints a signed one-use
token, user confirms). This is the moat vs. static incumbents (Hunter Vault / Fortune City are
offline & hand-authored). New game actions = new propose-tools.

**AI-only mechanics (static games can't do these):**
- **Procedural bosses/monsters** — agent reads worst category → generates a named villain +
  taunts + weaknesses; unique per user/month. (Powers the locked regret-monster.)
- **Adaptive quests** — designed from real behavior, not hardcoded thresholds.
- **Weekly "saga" recap** — transactions → an episodic RPG chapter (Wrapped × RPG).
- **Web-verified real-world challenges (AI-as-judge)** — e.g. "find a cheaper subscription";
  agent checks with Tavily + data, then the deterministic engine awards XP. Verifiability is
  unique to having web + data.
- **Customizable DM / nemesis** (part of R3) — persona with memory, reacts to specific habits.
- **AI rival "hunters"** *(deferred)* — LLM-simulated NPC competitors; solves the solo-app
  leaderboard problem without real users.
- **Natural-language "Spells"** — "freeze my dining spend" → a v1 automation rule via the existing
  propose→confirm pattern (add a `propose_rule` tool). Automations as a spellbook.

**LOCKED AI scope:** in → NL "Spells" → rules, web-verified challenges, procedural bosses/quests.
Deferred → AI rival hunters. (Customizable DM/nemesis stays part of R3.)

**Two-layer law (keeps it safe + testable):**
- **Deterministic engine = authority.** Events → stats/XP/boss-HP, pure `fold`, no LLM, tested.
- **Generative layer = flavor + judgment, never authoritative.** LLM reads engine state + data via
  tools, produces bosses/quests/narration/spells (cached in game tables, regenerable); any real
  change routes through propose→confirm. Anti-cheat: ground every AI judgment in real data, not
  user claims. Generate on **cadence** (weekly/monthly/refresh), not per-transaction, to bound Groq
  cost/latency.

## Retention / activation / growth / monetization (make-or-break)

Data: fintech 30-day retention ~10–12%; gamified +47% 90-day retention, +30–40% DAU; one study:
gamified group saved 27% more, 78% vs 31% retention. Streaks ≈ 2× daily retention (loss aversion);
silent bounded streak-freeze (2 max) is the proven design.

- **Daily-engagement solve (finance's core weakness):** you don't transact daily, so reward a
  daily reason that ISN'T spending — an **idle/overnight tick** (passive XP from *savings rate*,
  "collect" on open) + a **daily AI beat** (DM dispatch / daily quest / "interest accrued
  overnight"), one cached Groq call/day. **→ Idle layer is CORE retention infrastructure.**
- **Streaks on good behavior + silent streak-freeze:** streak = consecutive days "in the green"
  (under budget / Safe-to-Spend positive), not app-opens/spending; freeze applied silently,
  bounded at 2 (reduces money-anxiety, keeps loss aversion). Highest-ROI mechanic.
- **Onboarding = tutorial quest (activation):** setup as character creation (connect-bank = "summon
  power", first budget = "defenses", first goal = "quest", smallest debt = tutorial boss); AI
  generates a first monster from minimal data → solves cold-start + drives Plaid/budget.
- **Shareable victory cards (growth, later):** AI-generated, user-initiated season "Wrapped" /
  boss-kill cards; no numbers unless opted in.
- **Long arc (later):** rank ascension E→S / "7 Debt Lords" campaign / net-worth saga (net worth =
  long-arc XP).
- **Ethical monetization (later):** cosmetic-only + premium-AI/season-pass; NEVER pay-to-win on
  financial outcomes or paywall core finance.
- **Game-intensity slider (first-class):** Off (pure finance) / Ambient / Full RPG — serves both
  audiences, de-risks the theme shift, A/B-able.

**LOCKED first-class:** streaks + silent freeze, idle daily AI beat, onboarding tutorial quest,
game-intensity slider. **Documented direction (later):** shareable cards, long arc, monetization.

## Architecture (the law)

`game_state = fold(event_stream)` — a deterministic projection that **never writes to financial
truth** (accounts, balances, goals). Game-only state lives in reconstructable tables. Pure stat
engine in `services/game/`, deterministic and unit-testable. Events → toasts via
`notification_service` / `useToast`.

## Well-being & anti-dark-pattern charter (first-class)

Precedent: **Robinhood paid Massachusetts $7.5M** over confetti-on-trade, lottery/scratch rewards,
and push notifications that drove "frequent, risky, unsuitable" behavior; **FINRA is "increasingly
focused" on app game-like features**; randomized *purchasable* rewards (loot boxes) =
gambling/exploitation. Our mechanics are one bad choice away from these.

**Governing test:** every mechanic must answer *"does this improve the user's actual financial
health, or just our engagement metrics?"* If it only moves retention, cut it. (Also the marketing
story: "the gamified money app that's on your side.")

**Self-audit (mechanic → risk → line we hold):**
- Streaks → anxiety/shame → reward *good behavior* (days in the green), silent freeze + rest days,
  never shame, never punish hardship.
- Idle daily beat / push → compulsive checking (the Robinhood critique) → notifications deliver
  insight, frequency-capped, user-controlled, **never nudge a transaction**.
- Variable rewards / loot → gambling → **no real-money loot boxes ever**; variable rewards are
  cosmetic/XP only, never paid randomization.
- Debt bosses / regret-monster → debt shame → empowering, defeatable framing; regret-monster is
  reflective, never punitive.
- Rewarding actions → rewarding spending/logging (Hunter Vault/Fortune City/Robinhood) → **reward
  saving/paydown only** (the hardest line).
- Rivals/competition → comparison anxiety → opt-in, constructive, no shaming.

**Well-being features (ethics as product):**
- **Intensity slider doubles as an anti-addiction control** (users can dial *down*).
- **Radical transparency:** every game element can reveal the real number behind it.
- Setbacks soft & recoverable (income drop = "regroup," not "you lost"); numbers stay legible —
  gamey skin, not obfuscation.
- Note: no securities trading today (lower-risk than Robinhood), but the same principles + FINRA /
  state scrutiny apply the moment any investing feature appears.

## Loop hierarchy & smallest-lovable MVP

Failure mode to avoid: building everything, shipping nothing. Nested loops on financial rhythms:
- **Moment-to-moment (s):** open → Safe-to-Spend + avatar/HP + "collect overnight XP" micro-reward.
- **Daily (~1 min):** AI daily beat + a daily quest + streak check-in (stay in the green).
- **Weekly:** saga recap + quest refresh.
- **Monthly:** the roguelike run (draft modifier → survive → boss reveal/defeat → season reward).
- **Long arc (months–yrs):** rank ascension E→S, debt bosses felled, net-worth saga.

**MVP (validate the bet with ~5 components, not the full plan):**
1. Deterministic stat engine + character sheet (HP/Mana/XP from real data).
2. One Debt Boss (`Liability` + payment→damage + **defeat-by-date** via v1 forecast).
3. Streak + silent freeze.
4. Idle daily beat (overnight XP tick + one daily AI line).
5. Game-intensity slider (safe to ship to all).

**Defer past MVP:** roguelike months, broad procedural generation, web-verified challenges, NL
spells, rivals. **Sequencing truth:** v3 MVP depends on v1 (defeat-by-date needs the forecast;
spells need the rules engine) → **v1 ships first.**

## Build order

1. **Shared engine:** `services/game/` stat engine + game-only tables, incl. the append-only
   **engagement/achievement log**; the "never write to financial truth" boundary.
2. **R1 Debt Boss Battles** (flagship): `Liability` model + CRUD/UI; HP=balance; payments=damage,
   above-min=crit, APR=heal; **defeat-by-date via `project_cashflows`**; round-up auto-attack via
   the v1 generic-target rule; habit-monsters (no schema). Plus **R2 stat engine** minimal
   (character sheet + ambient avatar/level pip + toasts) alongside.
3. **X1 Roguelike months:** run/challenge selection store; monthly run state; drafted modifiers +
   random events (surprise expense = trap); cross-month meta-progression.
4. **Reflective tags + regret-monster:** optional "was it worth it?" tag on transactions →
   procedural monster from regretted spend.
5. **R3 AI Dungeon-Master narrator** (reuse `assistant_service` + Groq): roast/hype over the data,
   customizable persona with memory.
6. **AI generative layer** (new `propose_*` tools + cadence jobs, all non-authoritative):
   - **NL "Spells" → rules:** add a `propose_rule` agent tool reusing the propose→confirm/JWT
     pattern; plain-English → a v1 automation rule (needs v1 generic rule target).
   - **Procedural bosses/quests:** cadence job (monthly boss reveal / quest refresh) where the
     agent reads real spending → generates named villains + adaptive quests, cached in game tables;
     powers R1 bosses + the regret-monster + X1 run events.
   - **Web-verified challenges (AI-as-judge):** quest-verification flow grounded in data + Tavily;
     the deterministic engine (not the LLM) awards XP after a structured verdict.
7. **Retention/activation core (first-class):**
   - **Idle daily layer:** overnight passive-XP tick (from savings rate) + one cached daily AI
     "beat" → the daily-engagement solve.
   - **Streaks + silent freeze:** good-behavior streak (days in the green) + bounded (2),
     silently-applied freeze; lives in the engagement log.
   - **Onboarding tutorial quest:** setup-as-character-creation; AI first-monster from minimal
     data; drives Plaid link + first budget/goal.
   - **Game-intensity slider:** Off / Ambient / Full RPG user setting gating all game UI.
8. *Later (documented direction):* shareable victory cards, long arc (rank ascension / "7 Debt
   Lords"), ethical monetization (cosmetic + season pass), AI rival hunters, benchmark percentiles.

## Verification

- pytest: stat-engine determinism (same events → same stats); boss HP/damage/crit/victory; APR
  heal math; idempotent payment events; habit-monster derivation; percentile math; XP accrues only
  on good-behavior events (never on spending/logging).
- Migrations round-trip the `liabilities` (and any new game) tables on a scratch DB.
- E2E: add a debt → boss with HP=balance + defeat-by-date; payment → damage toast + date updates;
  pay to 0 → victory; over-budget category → habit monster.
- **Integrity:** game actions leave account balances/goals untouched.
- Manual `/run`: Arena + Character + ambient avatar render in the gamey theme; numbers legible.
